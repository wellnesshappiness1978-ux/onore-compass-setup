# アプリ全画面・7言語完全ローカライズ計画

## 目標
- 日本語、英語、簡体字、繁体字、韓国語、スペイン語、フランス語の切り替えを、全画面・ダイアログ・共有文・読み上げ文・エラー文・アクセシビリティ文まで一貫して反映する。
- 既存の型安全なTypeScript辞書を維持し、共通の `t('階層キー')` で参照できる仕組みに統一する。
- 計算ロジックや保存形式は変えず、画面に出る名称だけを選択言語へ変換する。

## 実装内容

### 1. 共通翻訳基盤を整える
- 7言語すべてで同じキー構造を持つ統合辞書と、変数差し込みに対応した型安全な `t()` を追加する。
- 現在コンポーネント内に分散している言語別オブジェクトを、機能別の翻訳辞書へ集約する。
- 日付、時刻、月、曜日、人数、件数、数値を選択言語の表記規則で整形する共通処理を用意する。
- ルートから子画面まで同じ選択言語を渡し、言語変更時に本文、ダイアログ、共有内容、ページタイトル、`lang` 属性を同時更新する。

### 2. 地球暦を完全翻訳する
- `HelioCalendar` に選択言語を接続し、タイトル、日時説明、天体図の説明、フェーズ、バイオリズム、カレンダー、方位、法人向け表示、予定登録文をすべて辞書化する。
- 天体配列を日本語名ではなく `sun / mercury / venus / earth / mars / jupiter / saturn` のIDで保持し、描画時に `t('planets.*')` を通す。
- 曜日、年月、フェーズ名、状態ラベル、カレンダー書き出し内容も各言語へ切り替える。
- `DayCompass` と `PlanPerksTab` から現在の言語を確実に渡す。

### 3. ホーム・ブランド・15占術を完全翻訳する
- `ArtsGuide` の「星々の引力と生命の原点」「アゴルメンの由来」「統合解析する15の分析ロジック」、分類、全占術名、説明、注意書き、ダイアログ文を7言語辞書へ移す。
- 占術一覧を安定したIDと翻訳キーで保持し、タイトル・背景・読み取る範囲を描画時に翻訳する。
- ホーム、オンボーディング、プロフィール、特性、今日、相談、ビジネス、設定、プラン案内、通知、音声・音楽、チーム機能に残る表示用日本語も同じ方式へ統一する。

### 4. フッター・法務・サポートを完全翻訳する
- ブランド名、免責事項、取引・キャンセル・返金、利用規約、プライバシーポリシー、問い合わせ、SNS共有、注意書きを共通辞書へ接続する。
- 既存の7言語法務本文を再利用し、フッター内のローカル辞書重複を解消する。
- 法務・サポート各ページの見出し、戻る導線、空状態、エラー、ページタイトルと説明を現在言語へ合わせる。
- 直接開いた法務ページでも保存済み言語を復元し、本文と見出しが同じ言語になるようにする。

### 5. アート名・九星・風水データをキー化する
- 「バースカラー曼陀羅アート」「出生宇宙創生図」、説明、読み込み、保存、共有、詳細欄、画像の代替説明を7言語化する。
- 九星は計算結果を番号IDで保持し、表示時に各言語名へ変換する。英語は `1 White Mercury` から `9 Purple Fire` まで直感的な名称にする。
- 八卦は `kan / kon / shin / son / ri / gon / da / ken / center` のIDへ分離し、翻訳表示では名称と方位を併記する。英語例は `Xun · Southeast`、中央は `Center` とする。
- 方位、五行、部屋、色、素材、植物、配置提案、九星の意味をすべて辞書参照に変える。
- 西洋星座、干支、天体名もID化し、選択言語の名称だけを画面へ出す。
- 計算関数は表示文を返さず、星番号・方位コード・要素IDなど言語非依存データを返す構造へ整理する。

### 6. 全画面の残存日本語を監査して置換する
- `src/components`、`src/routes`、表示に使われる `src/lib` を走査し、JSXテキスト、属性、通知、共有、Canvas/SVG文字、定数配列、エラー文の日本語直書きを翻訳キーへ置換する。
- 日本語そのものを正規の日本語辞書値として残すことは許容し、非日本語画面へ漏れる経路をなくす。
- 固有の保存キー、イベント名、計算ID、既存データ互換性は変更しない。

## 検証
- 翻訳キーの欠落、7言語間のキー差分、未定義キー、変数差し込み不足を自動テストする。
- 地球暦、九星、風水の既存計算テストを維持し、名称ID化後も計算結果が変わらないことを確認する。
- 7言語それぞれでオンボーディングから全7タブ、法務・サポート、ダイアログ、共有・保存操作まで表示確認する。
- 英語・スペイン語・フランス語・韓国語画面の日本語かな残存、簡体字と繁体字の取り違え、長文や長いラベルのはみ出しをデスクトップとモバイルで確認する。
- 最終ビルドと実行時エラーを確認し、翻訳漏れがあれば同じ改修内で解消する。

## 技術的な方針
- 新しい外部翻訳ライブラリやJSON移行は行わず、既存の `Record<Language, ...>` を拡張する。
- 翻訳キーは機能別階層（例: `helio.planets.sun`、`arts.methods.nameAnalysis.title`、`fengShui.stars.1`）に整理する。
- `t()` は存在するキーだけを受け付ける型にし、辞書不足をコンパイル時とテストで検出する。
- 既存の7言語別専門文、法務文、プラン文は活用し、英語だけへのフォールバックは設けない。
