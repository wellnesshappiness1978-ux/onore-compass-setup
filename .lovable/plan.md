# 占術データ × 宝飾曼陀羅 連動計画

## 目的
ユーザー本人の占術結果（数秘ライフパス数・主元素・本質タイプ）で、曼陀羅の「分割数」「背景オーラ」「中心宝石のカット」を変え、一人ひとり構造の違う作品にする。7色はそのまま、外部通信ゼロ・即時表示・2048×2048保存は維持。

## データの取り方（確認結果）
- ライフパス数・四柱推命の五行バランス（最多元素）・動物占いのグループは、すでにアプリ内の基本占術計算でプロフィール（生年月日・名前）から算出されている。
- データベースの占術結果テーブルは結果を保存する設計だが、曼陀羅はこの算出をその場で再利用する方が確実（ゲスト・未保存でも動き、通信待ちなし）。サインイン中も同じプロフィールから同じ値になる。
- 生年月日が無い場合は現行デザインのまま（既定値）。

## 連動ルール
1. ライフパス数 → 分割数
   - 1:8 / 2:12 / 3:9×2=18 / 4:16 / 5:10 / 6:12 / 7:14 / 8:16 / 9:18 / 11:22 / 22:24 / 33:36（各層の基本花弁数の主軸）
   - 6層の花弁数はこの主軸の倍数・約数で揃え、内側から外側へ密度が上がる構成を維持。
2. 主元素（五行の最多） → 背景オーラ・金粒の色味
   - 火=琥珀金 / 水=深海青 / 木=翡翠緑 / 土=トパーズ黄 / 金=白金
   - 漆黒背景の奥に低い不透明度の放射光として差すだけ。7色・金線は変えない。金粒は金色を保ったまま元素色へ1割ほど寄せる。
3. 本質タイプ → 中心宝石カット
   - 動物占いグループ：EARTH=八角形 / MOON=六角形 / SUN=十二角形
   - ライフパスがマスター数（11/22/33）なら放射スターカットを優先
   - 不明時は現行の八角形
4. 変わらないもの：7色の値と配置順、金線最上層、油彩ベース、宝石の不透明さ、星空、保存方式。

## 表示
- 曼陀羅の下に小さく「数秘◯ ・ 主元素◯ ・ ◯カット」を7言語で表示（任意で見える根拠）。

## 技術詳細
- `art-geometry.ts`：`MandalaTraits = { symmetry, element, gemCut }` 型と `mandalaTraitsFromCore(core)`（純関数）を追加。`compassMandalaLayout(colors, variation, radius, traits?)` が `symmetry` から各層 petals を算出（未指定時は現行値）。
- `MandalaCanvas.tsx`：`traits` prop を受け、`buildMandalaColorPlate` に渡す。宝石は `gemCutPoints(cut, r)`（6/8/12角・スター）からクラウン/パビリオン面を生成、既存の階調・不透明・筆触ロジックを共通化。背景に `elementAura` radialGradient、金粒色をmixHexで微調整。ライブ表示と保存は同一関数のまま。
- 呼び出し側（NineStarsPanel / CosmicAlchemyArtwork）：既存プロフィールから `computeCoreLayers` を `useMemo` で算出し traits を渡す。
- 言語ラベルは既存の型付き辞書に追加。
- テスト：ライフパス別の分割数、元素別オーラ色、4種カットの面数、traits無しで現行出力と一致、7色が未加工で含まれること、外部URLなし。Playwrightで3パターンの描き出しを確認。
